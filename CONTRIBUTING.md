# Contributing to lastcall

Thank you for your interest in contributing!

## Development Setup

```bash
git clone https://github.com/sakurablush/lastcall.git
cd lastcall
npm install
npm run dev
```

**Cursor users:** see [docs/contributing/cursor-skills.md](docs/contributing/cursor-skills.md) for agent skills and rules.

## Scripts

| Command                     | Description                                                  |
| --------------------------- | ------------------------------------------------------------ |
| `npm run build`             | Build ESM + CJS bundles                                      |
| `npm test`                  | Run unit and integration tests                               |
| `npm run test:log`          | Run tests with verbose proof logging (`LASTCALL_TEST_LOG=1`) |
| `npm run test:coverage`     | Run tests with coverage report                               |
| `npm run test:coverage:log` | Coverage + verbose logging                                   |
| `npm run docs:dev`          | VitePress docs dev server                                    |
| `npm run docs:build`        | Build docs for GitHub Pages                                  |
| `npm run lint`              | Lint source and tests                                        |
| `npm run typecheck`         | TypeScript type checking                                     |
| `npm run bench`             | Run shutdown benchmarks                                      |
| `npm run ci`                | Full local check (lint, format, typecheck, coverage, docs)   |

## Publishing

Releases are published to npm via GitHub Releases. Maintainers need an `NPM_TOKEN` repository secret configured for the publish workflow.

## What not to commit

Ephemeral AI assistant artifacts stay **local only** (see `.gitignore`, `.cursorignore`, `.kiloignore`):

- `.cursor/plans/` — implementation plans regenerated by Cursor
- `.kilo/plans/`, `.claude/plans/` — same for other AI tools
- `**/plans/`, `*-plan.md`, and similar plan filenames

Shared agent playbooks under `.cursor/skills/` and `.cursor/rules/` **are** tracked when present.

## Pull Request Guidelines

1. Fork the repository and create a feature branch
2. Add tests for new behavior
3. Ensure `npm run ci` passes (or at minimum `lint`, `typecheck`, and `test`)
4. Update `CHANGELOG.md` for user-facing changes
5. Keep PRs focused — one feature or fix per PR

## Code Style

- TypeScript strict mode
- Zero production dependencies
- Prefer small, focused modules
- Match existing naming and patterns

## Reporting Bugs

Use the bug report issue template and include:

- Node.js / Bun version
- Operating system
- Minimal reproduction code
- Expected vs actual behavior
